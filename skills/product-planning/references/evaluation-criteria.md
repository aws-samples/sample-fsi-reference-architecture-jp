# 商品企画ワークショップ 評価基準

Dry Run(Mode B)で `issues.md` に観点別の検出を記録する際、および Working Backwards Step 3 の最終評価時に参照します。成果物の品質評価ルーブリックです。

## 共通(両モードで適用)

| 観点 | 基準 |
|---|---|
| 論理的一貫性 | 各ステップの成果物が前ステップの結論に基づいているか |
| 成果物の自己完結性 | チャットを読み返さなくても内容が理解できるか |
| Mermaid の品質 | レンダリングエラーがなく、情報が正確に可視化されているか |
| 参加者体験の自然さ | 質問の流れが自然で、参加者の負荷が適切か |
| データの活用 | 提供されたデータが分析に適切に反映されているか |
| Web 調査の品質 | 情報不足時にクエリを工夫して粘り強く調査したか。ポジティブ・ネガティブ両面の情報を収集したか。具体的な数値・出典が記載されているか |

## マーケティング起点 固有

| 観点 | 基準 |
|---|---|
| 分析の網羅性 | PEST/5Forces/3C/VC の各フレームワークが適切に適用されているか |
| SWOT の根拠 | 各 SWOT 項目がどの分析から導出されたか明記されているか |
| 戦略と分析の整合 | クロス SWOT の戦略オプションが環境分析の根拠に基づいているか |
| STP の具体性 | セグメント/ターゲット/ポジショニングが具体的で実行可能か |
| 4P/4C の一貫性 | 売り手視点と買い手視点が矛盾していないか |

## Working Backwards 固有

| 観点 | 基準 |
|---|---|
| PR の顧客視点 | 社内用語を避け、顧客の言葉で書かれているか |
| PR の具体性 | 曖昧な形容詞を避け、具体的な価値が記述されているか |
| PR の構成準拠 | Amazon 推奨 7 段落構成(サマリー → 課題 → 解決策 → リーダー引用 → 顧客体験 → テスティモニアル → CTA)を満たしているか |
| PR の文字数 | 日本語で 1,200〜1,800 文字程度に収まっているか(必要項目を含めることが優先) |
| FAQ の充実 | 顧客向け 10〜15 問 + 内部向け 10〜15 問を含み、未確定事項は TBD として明記されているか |
| FAQ の誠実さ | 都合の悪い質問を避けず、リスクや不確実性が正直に記載されているか |
| 7 つの評価基準(Amazon) | 顧客定義、課題定義、ソリューション適合、行動変容、差別化、TAM/回収、制約 の各基準を満たしているか |
| PR/FAQ の一貫性 | PR で約束した体験が FAQ の詳細と矛盾していないか |
| レビューの深さ | 顧客体験・実現性・ビジネスモデルの 3 観点で十分に深掘りされているか |

## Amazon の 7 つの評価基準(Working Backwards Step 3 で使用)

| # | 基準 | 問い |
|---|---|---|
| 1 | 顧客定義 | 顧客は明確に定義されているか? |
| 2 | 課題定義 | 課題は明確に定義されているか? |
| 3 | ソリューション適合 | 提案されたソリューションは課題に対処しているか? |
| 4 | 行動変容 | 顧客は行動を変えてこのソリューションを買う/使うか? |
| 5 | 差別化(better/cheaper/faster) | 新商品はどの次元で既存品より better/cheaper/faster か? |
| 6 | TAM/回収 | TAM と投資回収は十分か? |
| 7 | 制約 | 克服すべき制約や問題は何か? |
