
# Web 検索の日付ポリシー

商品企画ワークショップ(`product-planning` スキル)およびプロンプト (`references/prompts/**/*.md`) 内で Web 検索を行う際の、時点に関する共通ルールです。Web 検索を含むあらゆる調査アクションの前に必ず適用してください。

## 原則

Web 検索で得る情報は **陳腐化します**。特に「市場規模」「競合動向」「規制」「技術トレンド」など商品企画で参照する情報は、数ヶ月で状況が変わります。検索クエリに年を入れるときや、結果を評価するときは、必ず「今が何年何月か」を把握した上で判断してください。

## 検索前の必須アクション

Web 検索を行う **前に**、以下を必ず実施します。

1. **現在日時を取得します**: システムが提供する現在日時を確認します(コンテキストの `current_date_and_time` 等、利用可能な手段で)。把握できないまま検索しないでください
2. **クエリに入れる年号を決定します**: 現在年を基準に、以下のいずれかで年号を扱います。
   - 現在年そのもの(例: 現在 2026 年 → `"2026"`)
   - 現在年 + 翌年(例: `"2026 2027"` や `"2026-2027"`)で直近の見込み情報を取りに行く
   - 「最新」「latest」「recent」などの相対表現を使う
3. **過去の年号をハードコードしない**: プロンプト例やテンプレートに `"2023"` `"2024"` `"2025"` などが書かれていても、そのまま使わないでください。実行時点の現在年に置き換えます

## 検索結果の扱い

検索結果を採用するかどうかを判断するときは、以下を確認します。

1. **公開日 / 更新日を確認**: 記事・レポートの公開日時を必ず確認します。2 年以上古い情報は、より新しいソースで裏付けが取れるまで採用しません
2. **古い情報は補足する**: やむを得ず古い情報を使う場合、成果物には「〇〇年時点のデータ」と明記し、読者が情報の新しさを判断できるようにします
3. **矛盾する新旧情報がある場合**: 新しいソースを優先しますが、「なぜ以前はこう言われていたのに今はこうなっているのか」を調べて成果物に含めると説得力が増します

## クエリ工夫の例

情報不足時にクエリを粘り強く工夫するときも、時点を意識します。

- 年号を外す / 「最新」に置き換える: `{業界} 市場規模 2024` → `{業界} 市場規模 最新`
- 範囲で指定: `{業界} トレンド 2026` → `{業界} トレンド 2025-2027`
- 予測・先読み: `{業界} 市場予測 2027` `{業界} outlook {current_year + 1}`
- 英語への切り替え時も同様に現在年を使う: `Japan P&C insurance market size 2026` のように

## 出典の記載

成果物(`01_environment.md` 等)に検索結果を反映するときは、**必ず公開日または取得日を出典と合わせて記載します**。例:

```
市場規模は 4.2 兆円(2026 年見込み、出典: XX 業界レポート 2026 年 3 月版、URL: ...)
```

## Mode B (Dry Run) での検知対象

Dry Run(品質検証)でワークショップをチェックする際、以下を「調査の不足・バイアス」カテゴリの問題として検知します。

- 現在年を確認せず Web 検索を実行した
- クエリに 2 年以上前の年号をハードコードして検索した
- 検索結果の公開日を確認せず、古い情報をそのまま成果物に反映した
- 成果物に公開日 / 取得日が記載されていない
