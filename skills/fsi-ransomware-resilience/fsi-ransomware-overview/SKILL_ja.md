# 金融機関向けランサムウェア対策:序章(Overview)

## Overview

ランサムウェア対策が扱う領域は、未然防止から侵入後の対応まで多岐にわたる。本スキルパッケージは、その中でも**ランサム攻撃を受けた際のレジリエンス向上、システム復旧基盤(復旧観点のワークロード設計)を支援すること**を目的とする。侵入を100%防ぐことは現実的に困難であり、侵入を前提として、いかに被害を封じ込め、迅速に事業を復旧できるかが、金融機関としての信頼性を左右する。

対応すべき領域(保護・検知・対応・復旧・組織対応)は多岐にわたるため、本パッケージはこれらについて体系的に設計提案を行う、または現状のワークロードを評価して改善につなげる、という形で支援する。ユーザーは以下の形でガイダンスを受けられる:

- AIエージェントとのチャット形式による対話的なガイダンス
- 自動生成されるレポート(HTML / Markdown)による設計提案・評価結果の確認
- 対策を段階的に実現していくための導入ロードマップ(短期・中期・長期)の提示

これらを通じて、AWSのベストプラクティスおよびソリューションアーキテクトが蓄積したナレッジに基づくランサムウェア対策設計を、効果的に導入することが可能になる。

本スキル(序章)は、この支援を受けるための入口として機能する。ランサムウェア対策に関する相談は、まず本スキルが受け止め、全体像の提示と適切なフェーズへのガイダンスを行う。本スキルを利用すると、以下のような対話・結果が得られる:

- ランサムウェア対策全般について「何を、どのフェーズで」検討すべきかが分からない場合、5フェーズ構成の全体像と、各フェーズが具体的に何を扱うかの説明を受けられる
- すでに相談したい内容(例: バックアップ設計、GuardDutyでの検知)が決まっている場合、対応する専門スキル(fsi-ransomware-protect 等)へ簡潔な概要説明とともに案内される
- 対応(Respond)・復旧(Recover)・組織対応(Organization)に関心がある場合、それらの将来提供予定の内容を知ることができる(現時点では実質的な相談には対応できないことも明示される)

本スキルが提供する内容:

- 本スキルパッケージ全体(保護・検知・対応・復旧・組織対応の5フェーズ構成)の概要説明
- ユーザーの相談内容・課題に応じた、該当フェーズへのガイダンス(振り分け)
- 各フェーズの現在の提供状況(利用可能 / 今後リリース予定)の明示

本スキルが対応する範囲:

- ランサムウェア対策に関する相談の入口・振り分け役に焦点を当てる
- 各フェーズの具体的な設計・評価・実装検討(チャットでの対話、レポート生成、ロードマップ提示等)は、それぞれの専用スキル(保護: fsi-ransomware-protect、検知: fsi-ransomware-detect、対応: fsi-ransomware-respond、復旧: fsi-ransomware-recover、組織対応: fsi-ransomware-organization)が担う。本スキルはそれらの活用をお客様にガイダンスするに留まり、自らバックアップ設計や検知態勢評価等の具体的な検討には踏み込まない

## 現在の提供状況

本スキルは 2026年7月時点の初回リリースでは暫定版である。保護(Protect)・検知(Detect)フェーズへの振り分けは実際に機能するが、対応(Respond)・復旧(Recover)・組織対応(Organization)の3フェーズは未リリースのため、これらに該当する相談は「今後リリース予定」の案内に留める。詳細な提供状況は Ransomware Resilience Framework セクションの表を参照する。

## Ransomware Resilience Framework(パッケージ全体の構成)

本パッケージは、本スキル(序章)を含めて6つのスキルで構成される。序章は入口・振り分け役であり、実際の対策検討は以下5つのフェーズスキルが担う。

| フェーズ | スキル名 | 提供状況 |
|---|---|---|
| 保護(Protect) | fsi-ransomware-protect | 利用可能 |
| 検知(Detect) | fsi-ransomware-detect | 利用可能 |
| 対応(Respond) | fsi-ransomware-respond | 今後リリース予定 |
| 復旧(Recover) | fsi-ransomware-recover | 今後リリース予定 |
| 組織対応(Organization) | fsi-ransomware-organization | 今後リリース予定 |

### 保護(Protect): fsi-ransomware-protect

バックアップ・データ保護環境のアーキテクチャ設計・既存環境評価を行う。マルチアカウントによる役割分離戦略、AWS Backup を中心としたバックアップアーキテクチャ、イミュータブル化(Vault Lock / S3 Object Lock)と暗号化、IAM / KMS / SCP によるポリシー設計、マルウェアスキャン戦略(AWS Backup マルウェアプロテクション、ECR コンテナ保護含む)、フォレンジック対応に備えたログ収集・保護、バックアップ運用の監視・監査、オンプレミス環境のバックアップ統合(AWS Backup Gateway / DataSync / Storage Gateway)を扱う。

### 検知(Detect): fsi-ransomware-detect

被害・脅威の検知と、検知した事象の分析を行う。サービス影響の検知(リソース監視・サービス監視・外形監視・業務指標監視)、セキュリティ攻撃の検知(Amazon GuardDuty の保護プラン、サードパーティ製品)、アラートを起点とした原因切り分け、収集済みログを活用した分析・調査(Amazon Detective、SIEM on Amazon OpenSearch Service)、検知・分析の集約・委任管理、分析ハードルが高い場合のフォレンジックベンダ連携の事前準備を扱う。

### 対応(Respond): fsi-ransomware-respond

検知された事象に対する隔離・証拠保全・本格的なフォレンジック分析への橋渡しを扱う想定(構想段階)。

### 復旧(Recover): fsi-ransomware-recover

バックアップからの復旧手順、復旧時の感染チェック、サービスの段階的な復帰を扱う想定(構想段階)。

### 組織対応(Organization): fsi-ransomware-organization

有事の際の組織体制構築、社内外コミュニケーションフロー、規制当局・関係機関への報告等の組織運用面の考慮を扱う想定(構想段階)。

## Reference Foundations

本スキルが示す5フェーズ構成は、NIST Cybersecurity Framework (CSF) の考え方を土台としつつ、金融機関向けランサムウェア対策の実務に即した区分として整理している。各フェーズの詳細な権威ある情報源は、各フェーズの専用スキル(fsi-ransomware-protect / fsi-ransomware-detect 等)の Reference Foundations セクションを参照する。

## Common Tasks

### Workflow A: 入口ガイダンス

本スキルは単一の Workflow(入口ガイダンス)で構成される。ランサムウェア対策に関するあらゆる相談は、まず本 Workflow で受け止める。

#### 発動条件

ランサムウェア対策に関する相談全般に対応する。「何から始めればいいか分からない」「全体像を知りたい」といった曖昧な問いはもちろん、特定フェーズに近い話題(バックアップ、検知等)であっても、まず本スキルが概要を示した上で該当フェーズへ橋渡しする入口として機能する。

#### ゴール

Workflow A 完了時、ユーザーは以下を得ている:

1. 自身の相談に対応するフェーズの特定、または全体像の理解
2. 該当フェーズの概要説明と活用への誘導、または対応/復旧/組織対応の場合は今後リリース予定であることの案内

## Constraints

### MUST(必須)

- **OV-C1**: You MUST 本スキルの対応中に、他フェーズスキルのファイル(SKILL.md / SKILL_ja.md / references/ 等)を読み込んで動作してはならない(スキル独立性の原則)。他フェーズへの言及は、常に「活用をお客様にガイダンスする」表現に留める
- **OV-C2**: You MUST ユーザーの最初の問いで、保護/検知/対応/復旧/組織対応のいずれかのフェーズ名、またはそれに相当する具体的なサービス・トピックが明言されていない場合、処理ステップ Step 1 に記載された確認文を一言一句そのまま、Markdownの箇条書き構造(改行・インデントを含む)を保持したまま、最初の応答の冒頭で出力する。全体像の説明・要約・言い換えを行ったり、確認文の提示より前に他の内容(Ransomware Resilience Framework の表等)を出力してはならない。箇条書きをプレーンテキストの1段落に連結して出力してはならない。最初の問いで具体的なフェーズ名・トピックが明言されている場合のみ、この確認を省略できる
- **OV-C3**: You MUST Step 2(全体像提示)において、処理ステップ Step 2 に記載された全体像説明文を一言一句そのまま、Markdownの構造(見出し・段落・箇条書き・表・改行を含む)を保持したまま出力する。要約・言い換え・省略を行ってはならない。末尾の選択肢は B-1〜B-5 のみとし、A(全体像の再確認)を再掲してはならない
- **OV-C4**: You MUST 保護(Protect)・検知(Detect)への誘導時、それぞれの概要を1〜2行で説明した上で活用を案内する。ただし、OV-C2 の確認を省略した場合は、この概要説明を重ねて行わず、直接活用案内・誘導のみを行う
- **OV-C5**: You MUST 対応(Respond)・復旧(Recover)・組織対応(Organization)に該当する相談には、該当フェーズの概要を紹介した上で、現状は利用不可であり今後リリース予定であることを明示する
- **OV-C6**: You MUST Step 2(全体像提示)の末尾で提示する選択肢に、B-1〜B-5 の5択(対応/復旧/組織対応を含む)を必ず含める。利用可能なフェーズ(保護/検知)のみに選択肢を縮退させてはならない

### MUST NOT(禁止)

- **OV-C7**: You MUST NOT バックアップ設計・検知態勢の評価等、各フェーズスキルが担う具体的な設計・評価を本スキル自身で実施しない
- **OV-C8**: You MUST NOT 対応/復旧/組織対応の相談に対して、リリース予定日・時期を断定的に提示しない

### SHOULD(強く推奨)

- **OV-C9**: You SHOULD ユーザーが複数フェーズに関心を示した場合、該当する複数フェーズの概要を並べて説明し、ユーザーにどちらから進めるか選んでもらう
- **OV-C10**: You SHOULD 誘導後もユーザーが全体像について対話を続けたい場合、本スキル内で概要レベルの説明を継続してよい

### MAY(可)

(現時点では該当項目なし。将来的な拡張に備えてセクションを残す)

## Troubleshooting

Skill 内部の判断指針(Claude が判断に迷いやすいケースへの対処)。

| # | Q(迷いやすいケース) | A(判断指針) |
|---|---|---|
| 1 | ユーザーが非常にピンポイントな技術質問(例:「Vault Lock のコンプライアンスモードとガバナンスモードの違いは?」)を最初から投げてきた場合 | スキルの発動制御は各スキルの description に対する意図マッチングによるため、本スキルを必ず経由するとは限らない(fsi-ransomware-protect 等が直接発動する場合がある)。本スキルが発動した場合は、OV-C2 に従い該当フェーズ・トピックが明言されているため確認文の出力を省略し、直接活用案内・誘導を行う |
| 2 | ユーザーが対応/復旧/組織対応の詳細な相談を強く求めてきた場合 | OV-C5・OV-C8 に従い、今後リリース予定であることを明示する。押し付けにならない範囲で、保護/検知の観点で現時点から着手できる備えがあれば、そちらへの水平展開を提案してもよい |
| 3 | ユーザーが複数フェーズに関心があると答えた場合 | OV-C9 に従い、複数フェーズの概要を並べて説明し、ユーザーにどちらから進めるか選んでもらう |
| 4 | ユーザーが「FISC のこの条文に対応するには?」のように規制条文への具体マッピングを求めてきた場合 | 具体条文への適合性は判定せず、一般論レベルの観点提示に留める。組織の規制対応部署・コンプライアンス部署への確認を促す |
| 5 | ユーザーが Step 1 で A(全体像を知りたい)を選んだ後、再度「A. まずは全体像から知りたい」という選択肢が表示され、同じ質問がループしているように見える場合 | OV-C3 の違反。Step 2 の末尾は B-1〜B-5 のみとし、A を再掲しない。すでに全体像を提示済みのユーザーに A を再度選ばせる必要はない |
