ABOUT THIS REPORT

本レポートは、AWS 金融リファレンスアーキテクチャ日本版で公開されているランサムウェア対策向けの SKILL を用いて、お客様のランサム対策アーキテクチャの全体設計をまとめたものである。AWS Well-Architected Framework Financial Services Industry Lens、AWS Blueprint for Ransomware Defense 等の AWS 公式ガイダンスをベースに、金融機関の文脈で求められる設計考慮を加味したうえで、お客様環境に合わせた設計提案を行っている。

ランサムウェア対策は、保護（Protect）・検知（Detect）・対応（Respond）・復旧（Recover）の 4 つの観点で体系的に整備することが有効である。本レポートは、このうち 保護（Protect）フェーズ ― 攻撃を受けてもデータを失わない・改ざんされないバックアップ環境の設計 ― を対象とする。検知・対応・復旧の各フェーズは別途扱う。

各設計領域には、対応の優先度・スピード感を示すフェーズ(短期 / 中期 / 長期)を付している。具体的な実装手順・設計判断の根拠・期待される防御効果については、本レポートに続けて「ロードマップ詳細レポート」を生成することができる。

Overall Direction

本設計は、既存の AWS Organizations + 約 200 アカウントの構造 をそのまま活かしつつ、Backup / 隔離 / リカバリの 3 アカウントを新設して責務分離を実現する構成を目標形とする。Control Tower は未利用とのことだが、本設計はその前提でも成立する。

ランサム対策の要は、業務アカウントが侵害されてもバックアップが残り、暗号化キーが奪われても復号でき、削除操作が組織側から防がれ、感染データのリストアを未然に検知できる構造を作ることである。本提案ではこれを「3-2-1 ルール × 多層防御 × 責務分離」の 3 本柱で実装する。

RDS / Aurora を含む幅広いリソースが保護対象であるため、LAG vault と通常 Vault + Vault Lock のハイブリッド構成を採用する。基幹系の数分〜1 時間ごとの取得が求められるバックアップ要件に対しては、対応リソース(RDS / Aurora / S3)で Continuous backup (PITR) を活用し、その他リソースはスナップショット間隔で対応する。

200 アカウント規模のため、個別アカウント単位の運用は破綻する前提で、組織共通のバックアップポリシーを OU + タグで配り分ける運用設計を採用する。なお、組織横断のアカウント構成変更は影響範囲が大きく対応負荷も高いため、本設計では長期の取り組みと位置づけ、まずは既存環境への影響が小さい予防的統制から着手する段階的アプローチを推奨する。

既存環境を踏まえた重要な判断ポイント

Key Decisions
  1. 既存 Organizations 構造を維持しつつ、ランサム対策専用 OU / アカウントを追加する形を推奨。Control Tower はランサム対策のためだけに導入する必要はない。
  2. 200+ アカウント規模では、バックアップポリシーを業務影響度別に 2〜3 種類用意して OU / タグで配り分けるのが現実的。
  3. 「Organizations 管理アカウントへの権限集中」を解消する好機。Backup 管理を新設の Backup アカウントへ委任することで、自然にこの方向に揃う。
  4. RDS / Aurora / S3 は Continuous Backup (PITR) を基幹系で活用し、数分ごとの取得が求められるバックアップ要件に対応。PITR 非対応リソースは業務側静止点運用と組み合わせたスナップショット設計が必要。

Backup Policy の配り分けとデータフロー

200+ アカウントへは、OU 単位の Backup Policy(Critical / Standard / Dev-Test の業務影響度別)と、タグ(Backup-Tier 等)によるリソース割当を組み合わせて配布する。タグ命名の統一には Organizations のタグポリシーを併用する。データフローは以下の 3 経路で構成する。

コピー経路主目的
業務(東京) → 業務(大阪)3-2-1 ルール「異なる場所」、リージョン障害・自然災害対策(DR 兼用)
業務(東京) → 隔離(東京)3-2-1 ルール「異なるアカウント」、ランサム・内部不正・誤操作対策(本丸)
隔離 → リカバリ有事の復旧着手の迅速化、フォレンジック分析・リストアテストの場(平時から継続コピー推奨)
Notes RDS / Aurora 等 LAG vault 非対応リソースは通常 Vault + Vault Lock、EC2 / EBS / S3 等 LAG 対応リソースは LAG vault に分割保護するハイブリッド構成とする。LAG vault のサポートリソースは AWS の機能拡張で随時変わるため、設計時に公式ドキュメントで最新の対応リソースを確認する。

クロスアカウントコピーを支える 6 つのポリシー制御ポイント(概要)

Organizations 委任 / 業務側 KMS キーポリシー / バックアップ実行ロール / リストア実行ロール / Vault アクセスポリシー / コピー先 KMS キーポリシー の 6 点で構成する。Vault アクセスポリシーで許可可能なクロスアカウントアクションは backup:CopyIntoBackupVault のみで、コピー先 Vault への破壊的操作はクロスアカウントでは構造的に不可能となる。各制御ポイントの詳細は、続けて生成できるロードマップ詳細レポートで扱う。

SCP による予防的統制(短期で着手すべき領域)

Vault / リカバリポイント削除、KMS キー削除・無効化、CloudTrail / Config 停止、Log 集約バケット改変、組織離脱 を Deny する。SCP は管理アカウント自体には適用されないため、管理アカウントの権限肥大化を避ける委任設計が前提となる。

Caution SCP / Vault Lock (Compliance) / Multi-party approval は強力な統制だが、緊急時の例外手順(Break Glass ロール、代替承認者、保持期間設計ミスへの対処)を組織のセキュリティ・運用・コンプライアンス部門と事前に合意しておく。

長期
Design Core 「感染済みバックアップから復旧して再感染する」事態を防ぐため、平時からバックアップに対するスキャンを実施する。バックアップ保護の基盤が整った後の高度化施策であり、AWS Backup Malware Protection を主軸に、必要に応じて 3rd party 製品を併用する。長期に位置づける。

L
ログ収集・保護
短期
Design Core 「ランサム被害後のフォレンジック分析を可能にする」ためのログ基盤。収集と保護の 2 軸で設計する。既存の Log 集約用アカウントを核として不足分を補強する形であり、特に既存 S3 への保護強化は影響が小さく即効性が高いため、短期に位置づける。

CloudTrail(組織トレイル)、Config(Aggregator)、VPC Flow Logs、Route 53 Resolver クエリログ等を Log 集約用アカウントへ集約する。既存 Log 集約用 S3 には S3 Versioning + Object Lock (Compliance mode) + MFA Delete + 最小権限化を適用する。ログ停止・削除には予防(SCP)・検知(EventBridge)・自動復旧(Config Rules)・データ保全(Object Lock)の 4 段階防御で対応する。

Notes ログを取り揃えても、実際のフォレンジック分析は高度な専門性を要する。平時からフォレンジックベンダとの契約を準備しておくことを推奨する。Security Lake / Control Tower は必須ではなく、効率化要素として部分導入を検討する。
A
バックアップ運用の監視・監査
長期
Design Core 「バックアップが想定通りに動作し続けているか」「設定が変更されていないか」を継続監視し、監査証跡を継続的に確保する。組織横断の集中管理基盤の整備にあたり、Backup アカウントへの集約が前提となるため、長期に位置づける。

クロスアカウントモニタリング(リアルタイム状況把握)と AWS Backup Audit Manager レポート(ジョブレポート + コンプライアンスレポート)を併用する。200+ アカウントの規模では、個別ログイン不要で全社状況を一望できる効率化効果が大きい。

Notes Audit Manager レポートの配信先は Backup アカウント所有 S3 のみ(クロスアカウント S3 配信は非サポート)。レポート保管 S3 にはログ保管 S3 と同等の保護を適用する。監査では Vault Lock 適用状況・保持期間・暗号化設定の逸脱を自動的に証跡化でき、規制対応・監査対応の工数削減が見込める。

段階的ロードマップ概観

短期 既存環境への影響が小さく即効性のある対策

中期 個別アカウント単位で完結する対策

  • Vault Lock(Governance mode 検証 → Compliance mode)の適用
  • リソース暗号化状況の点検と KMS CMK への揃え込み

長期 組織横断の構成変更・集中管理基盤の整備・高度化

  • 組織横断 Backup Policy の全 Prod 展開、クロスアカウント・クロスリージョンコピーの全面適用
  • クロスアカウントモニタリング + Audit Manager による監視・監査の集中管理
  • AWS Backup Malware Protection の全社展開、ECR 保護強化

  • フォレンジックベンダとの平時契約、他フェーズ(Detect / Respond / Recover)Skill との統合
