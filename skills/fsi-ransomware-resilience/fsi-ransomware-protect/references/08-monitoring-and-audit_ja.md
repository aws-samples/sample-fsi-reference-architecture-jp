# バックアップ運用の監視と監査

## 概要

本リファレンスは、本スキルが採用するバックアップ運用の継続的な監視と監査について示す。ランサムウェア対策の文脈では、バックアップを取得・保護する仕組みを構築するだけでは不十分であり、それらが想定通りに動作し続けているか、設定が変更されていないかを継続的に監視することが重要となる。また、規制対応・監査対応の観点では、バックアップアクティビティの証跡を継続的に記録し、後日参照可能な形で保管することが求められる。

本リファレンスでは、AWS Backup が提供するクロスアカウントモニタリング機能、AWS Backup Audit Manager によるレポート機能、監視・監査の実装アカウントの整理、金融機関の文脈での設計判断について整理する。

マルチアカウント構成における Backup アカウントの位置づけは [01-multi-account-architecture.md](./01-multi-account-architecture.md)、ログ収集・保護全般は [07-log-collection-and-protection.md](./07-log-collection-and-protection.md) を参照する。

## 基盤メカニズム: AWS Backup の組織横断管理機能

本スキルが採用するマルチアカウント構成では、組織内の複数アカウントで実行されるバックアップ・コピー・リストアジョブを Backup アカウント（AWS Backup の delegated administrator）から一元的に把握できる仕組みが用意されている。AWS Backup は、組織横断の運用・監査を実現するために以下の2つの機能を提供している。

| 機能 | 性質 | 主な役割 |
|---|---|---|
| **クロスアカウントモニタリング（Cross-account monitoring）** | リアルタイムの状況把握 | バックアップ・コピー・リストアジョブの実行状況を組織横断で確認 |
| **AWS Backup Audit Manager レポート** | 定期的な監査証跡の出力 | バックアップアクティビティを S3 に自動レポート出力 |

両機能は役割が異なるため、本スキルでは併用することを推奨する。クロスアカウントモニタリングで日常的な運用状況を把握しつつ、Audit Manager レポートで監査証跡を継続的に確保する設計となる。

## クロスアカウントモニタリング

### 機能概要

クロスアカウントモニタリングは、AWS Organizations 配下のアカウントで実行されたバックアップ・コピー・リストアジョブを、Organizations 管理アカウントおよび Backup アカウント（delegated administrator）から一元的に確認できる機能である。各アカウントに個別ログインしてジョブ状況を確認する必要がなくなり、組織横断の運用が効率化される。

### 確認可能な情報

AWS Backup コンソール上で以下のような情報が確認可能である。

- ジョブのステータス（成功・失敗・進行中等）
- アカウント ID
- リソース名・リソース ID・リソースタイプ
- ジョブ ID
- 実行日時

ジョブの種類別にバックアップジョブ・リストアジョブ・コピージョブとして整理されており、アカウント ID、ステータス、ジョブ ID 等によるフィルタリング・検索も可能となる。

### 有効化に関する注意点

クロスアカウントモニタリングはオプトイン式の機能であり、Organizations 管理アカウント側で有効化する必要がある。有効化後に作成されたジョブのみが集約ビューに表示される仕様であり、過去のジョブを遡って表示することはできない。

無効化した場合、過去のジョブは終了状態到達後の一定期間は表示されるが、それ以降は表示されなくなる。具体的な保持期間は機能拡張により変わる可能性があるため、AWS Backup 公式ドキュメントの [Managing AWS Backup resources across multiple AWS accounts](https://docs.aws.amazon.com/aws-backup/latest/devguide/manage-cross-account.html) の最新版を参照することを推奨する。

## AWS Backup Audit Manager レポート

### 機能概要

AWS Backup Audit Manager は、組織内のバックアップアクティビティを自動的に S3 にレポート出力する機能を提供する。継続的な監査証跡の確保や、規制対応の一環として活用することが可能となる。レポートの自動出力により、監査対応時にあらかじめ用意された証跡を提供できる体制を整えることができる。

### レポートの種類

| レポートの種類 | 内容 |
|---|---|
| **ジョブレポート（Jobs report）** | 過去24時間に完了したジョブと、すべてのアクティブなジョブの情報を出力。Vault プロパティ、バックアッププラン構成、ライフサイクル設定等のコンテキストも含む |
| **コンプライアンスレポート（Compliance report）** | リソースレベル・適用中のコントロール状況をモニタリングしたレポート |

ジョブレポートには Vault タイプ・Lock ステータス・暗号化情報・バックアッププラン名・スケジュール・保持期間等のコンテキスト情報が含まれるため、追加の API 呼び出しなしで包括的なジョブ情報を取得できる構造となる。

### 出力仕様

| 項目 | 内容 |
|---|---|
| 配信先 | 指定した S3 バケット（レポートプラン作成元のアカウントが所有する S3 バケットのみ。クロスアカウント S3 配信は非サポート） |
| 出力形式 | 同一リージョン・同一アカウント宛の場合は CSV または JSON、それ以外は CSV |
| 頻度 | 24時間ごと（自動）。オンデマンド実行も可能 |

実行タイミングはパフォーマンス上の理由から数時間のランダム化が入る仕様となっている。

### スコープと制約

- 全アカウント保有者がクロスリージョンレポートを作成可能
- Organizations 管理アカウントおよび Backup アカウント（delegated administrator）はクロスアカウントレポートも作成可能（メンバーアカウントの活動を集約したレポート）
- 1 AWS アカウントあたりのレポートプラン数には上限が設けられている

詳細な仕様は AWS Backup 公式ドキュメントの [Working with audit reports](https://docs.aws.amazon.com/aws-backup/latest/devguide/working-with-audit-reports.html) の最新版を参照することを推奨する。

### マルウェアスキャン結果のレポート活用

AWS Backup Audit Manager のレポートでは、GuardDuty Malware Protection for Backup によるスキャンジョブの履歴も確認することが可能である。スキャン結果（クリーン / 脅威検出）の継続的なモニタリングを Audit Manager レポートで行うことで、バックアップの健全性を組織横断で把握する運用が実現できる。マルウェアスキャンの詳細は [05-malware-protection.md](./05-malware-protection.md) を参照する。

### レポート保管 S3 バケットの保護

Audit Manager レポートを保管する S3 バケットは、本スキルが採用するログ保管 S3 バケットと同等の保護機構を適用することを推奨する。具体的には、S3 Object Lock、S3 Versioning、MFA Delete、最小権限化されたアクセス制御の組み合わせとなる。詳細は [02-immutability.md](./02-immutability.md)（S3 Object Lock）および [07-log-collection-and-protection.md](./07-log-collection-and-protection.md)（S3 多層防御）を参照する。

## 監視・監査の実装アカウントの整理

本スキルが採用するマルチアカウント構成における監視・監査機能の実装アカウントは以下となる。

| 機能 | 主な実装アカウント |
|---|---|
| クロスアカウントモニタリングの有効化 | Organizations 管理アカウント |
| クロスアカウントモニタリングの確認 | Organizations 管理アカウントおよび Backup アカウント |
| Audit Manager レポートプランの作成 | Backup アカウント（クロスアカウントレポート作成のため delegated administrator として実行） |
| レポート保管 S3 バケットの配置 | Backup アカウント（レポートプラン作成元アカウントが所有する S3 バケットへの配信が制約のため） |

組織横断の運用・監査機能を Backup アカウントに集約することで、管理運用が効率化される構成となる。

## 金融機関の文脈での設計判断

### 規制対応・監査対応への活用

金融機関では、内部監査・外部監査・規制当局による検査の際に、バックアップ運用の証跡提示が求められるケースが多い。本リファレンスで述べた Audit Manager レポートを活用することで、以下のような対応が可能となる。

- 日次のバックアップアクティビティを自動的に S3 に記録し、監査要求時に即座に証跡を提示する
- Vault Lock の有効化状況、保持期間設定、暗号化設定等を Compliance report で継続的にモニタリングする
- バックアップポリシーの遵守状況を継続的に検証し、設定逸脱を早期に検知する

ただし、特定の規制条文への適合性判定は本スキルのスコープ外であり、組織の規制対応部署・コンプライアンス部署と連携して判断することを推奨する。

### レポート保管期間の設計

監査証跡として保管するレポートの保持期間は、組織内ルール・規制要件に応じて設計することを推奨する。金融機関では業務記録・取引記録の保管期間が法令や業界規制で定められているケースが多く、Audit Manager レポートも同等の保管期間を設定することが望ましい。長期保管はコスト効率を考慮し、Amazon S3 Glacier 等のコールドストレージへ移行する設計を併用することが可能となる。

## 対策効果のサマリ表

本リファレンスで扱う各設計要素が、ランサムウェア対策としてどのリスクに有効かを整理する。

| 設計要素 | 防御するリスク | 有効なシナリオ |
|---|---|---|
| クロスアカウントモニタリングによる組織横断の状況把握 | バックアップ実行失敗の見逃し | アカウント数が多い組織での運用効率化、想定外のジョブ失敗の早期検知 |
| Audit Manager ジョブレポートによる証跡の自動記録 | 監査対応時の証跡不足 | 規制対応・内部監査・外部監査での証跡提示 |
| Audit Manager コンプライアンスレポートによる設定遵守の継続検証 | バックアップポリシー設定の逸脱 | Vault Lock 設定漏れ、保持期間の意図せぬ短縮等の早期検知 |
| マルウェアスキャン結果の Audit Manager 経由のモニタリング | 感染検出の見逃し | 組織横断でのスキャン結果の継続的把握 |
| レポート保管 S3 への多層防御 | レポート自体の改ざん・削除 | 監査証跡として用いるレポートの完全性確保 |
| Backup アカウントへの監視・監査機能集約 | 各アカウントでの個別運用による設定不整合 | 組織横断の統一的な運用・監査基盤の確保 |
