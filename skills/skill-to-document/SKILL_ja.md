# Skill to Document

Agent Skillパッケージを、プロフェッショナルなフォーマットのPDF、DOCX、またはHTMLドキュメントに変換する。
スキルのSKILL.mdおよび参照される全Markdownファイルを読み込み、論理的な目次を構築し、
日本語の完全なドキュメントとして出力する。

## 前提条件

- **Python**: 3.10以上
- **uv**: Pythonパッケージマネージャ（[インストールガイド](https://docs.astral.sh/uv/getting-started/installation/)）
- **OS**: macOSまたはWindows（日本語システムフォントを自動検出する）

同梱のPythonスクリプト（`scripts/`）がfpdf2およびpython-docxを使用してPDF・DOCX生成を行う。
依存パッケージは`scripts/pyproject.toml`で管理され、`uv`による初回実行時に自動インストールされる。

## 実行ガイドライン

- 可能な限りサブエージェントとしてこのスキルを実行し、呼び出し元のコンテキスト消費を回避する。
- 処理の複雑さのため、全ステップでextended thinking（ultrathink / super think）を使用する。

## 対応出力形式

3つの出力形式が常に利用可能である — 外部スキルへの依存は不要：

1. **HTML** — 組み込み対応、追加ツール不要。同梱の`assets/style-template.css`を使用する。
2. **PDF** — `scripts/generate_pdf.py`がfpdf2とOS標準日本語フォントで生成する。
3. **DOCX** — `scripts/generate_docx.py`がpython-docxで書籍品質のスタイルで生成する。

## アーキテクチャ

このスキルはHTML中心のアプローチを採用する：

```
エージェント (Step 1-7)
    │
    ▼  常にHTMLを先に生成 (Step 7)
    ├── HTML形式の場合 → .html + style.css をそのまま出力
    ├── PDF形式の場合  → HTMLを scripts/generate_pdf.py に渡す → .pdf
    └── DOCX形式の場合 → HTMLを scripts/generate_docx.py に渡す → .docx
```

エージェントは常にHTMLを中間表現として生成する。PDFおよびDOCXの場合、
生成されたHTMLファイルを対応するPythonスクリプトに渡して変換する。

## ワークフロー

以下のステップを順番に実行する。致命的なエラーが発生した場合は停止して制御を返す。

### Step 1: 出力形式の決定

```
ユーザーが明示的に形式を指定した？
  ├─ はい (pdf)  → PDF を使用
  ├─ はい (docx) → DOCX を使用
  ├─ はい (html) → HTML を使用
  └─ いいえ      → HTML を使用（デフォルト）
```

全形式が常に利用可能である。利用可能性の確認は不要である。

### Step 2: 対象スキルの特定

ドキュメント化するスキルを特定する：

- **ローカルスキル**: スキル名と既知のスキルディレクトリからSKILL.mdのパスを解決する。
- **リモートスキル（URI）**: 指定されたURIからSKILL.mdの内容をフェッチする。フェッチに失敗した場合、エラーを出力して停止する：
  ```
  エラー: SKILL.md を取得できませんでした。
  URI: <uri>
  理由: <エラー詳細>
  ```

SKILL.mdのフロントマターから`name`と`description`を抽出する。

### Step 3: コンテンツの収集

SKILL.mdを起点として、参照ファイルを再帰的に収集する：

1. SKILL.md内の全相対ファイル参照（リンクおよび明示的パス）を解析する。
2. **含める**: Markdownファイル（`.md`）— 全内容を読み込み、その参照も再帰的に辿る。
3. **付録として含める**: JSON Schemaファイル（`$schema`またはスキーマ的構造を持つ`.json`）— ドキュメント末尾に参考資料として追加する。
4. **除外**: アプリケーションコードおよびスクリプト（`.py`, `.js`, `.ts`, `.jsx`, `.tsx`, `.mjs`, `.cjs`, `.sh`, `.bash`, `.tf`, `.hcl`, IaCマニフェストである`.yaml`/`.yml`, `package.json`, `tsconfig.json`等）。

リモートスキルの場合、SKILL.mdのURIベースからの相対パスで参照Markdownファイルをフェッチする。

Markdownで参照される画像ファイル（`.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.bmp`）について：
- 一時ディレクトリにダウンロードする。
- 元のパスからローカル一時パスへのマッピングを記録する。
- **ドキュメント生成完了後、全ての一時ファイルを必ず削除する。**

### Step 4: 目次の構築

収集したMarkdownコンテンツから、論理的なドキュメント構造を構築する：

1. Markdownの見出し（`#`, `##`, `###`等）を章・節・項の階層にマッピングする。
2. 複数ファイルのコンテンツを一貫した構造に統合する — SKILL.mdの構造を主要なアウトラインとして使用する。
3. 章番号を付与する（1, 1.1, 1.1.1 等）。
4. ToCを`{番号, タイトル, レベル}`エントリの順序付きリストとして生成する。

### Step 5: ドキュメント本文の生成

ドキュメント本文を日本語で作成する：

- 全ての英語コンテンツを日本語に**翻訳**する。技術用語、AWSサービス名、CLIコマンド、コードスニペットは原文のまま保持する。
- **要約しない** — 原文の全テキストを忠実に翻訳して使用する。
- Step 4で決定した論理構造を維持する。
- コードブロック、テーブル、リストはそのまま保持する（周囲の説明文のみ翻訳）。

### Step 6: 画像の配置

コンテンツ内で見つかった各画像参照について：

- ドキュメント内の対応する位置に画像を挿入する。
- ページマージン内に収まるよう画像をスケーリングする（最大幅: コンテンツ領域幅）。
- 画像ファイルが利用できない場合、プレースホルダーを挿入する: `[画像: <元のパス> — 取得不可]`。

### Step 7: HTML生成

最終出力形式に関わらず、常にHTMLドキュメントを先に生成する。

読みやすく印刷にも適したHTMLドキュメントを生成する：

- このスキルに同梱されている`assets/style-template.css`を出力サブディレクトリに`style.css`としてコピーする。
- `style.css`をリンクする`<スキル名>.html`を作成する。
- 参照される画像を`images/`サブディレクトリにコピーし、`src`属性を更新する。

HTMLには変換スクリプトが解析するための適切な構造CSSクラスを含める必要がある：
- `.title-page` — タイトルページのdiv
- `.toc` — 目次のdiv
- `.chapter` — 各章のdiv
- `.appendix` — 付録のdiv

#### タイトルページ

中央揃えで以下を含む：
- **ドキュメントタイトル**: スキルの`name`と`description`から適切な日本語タイトルを導出する。
- **スキル名**: `name`フィールドの値そのもの。
- **日付**: 現在の日付を`YYYY/MM/DD`形式で表示。

#### 目次ページ

Step 4で構築したToCを章番号とタイトル付きで出力する。

#### 本文

各章を順番に出力し、トップレベルの章ごとに改ページする（`.chapter`クラスを使用）。

#### 付録（該当する場合）

Step 3でJSON Schemaやその他の参考ファイルが収集された場合、「付録 (Appendix)」セクションとしてドキュメント末尾に出力する。

### Step 8: 最終形式への変換（HTML以外の場合）

要求された形式がPDFまたはDOCXの場合、同梱のPythonスクリプトで生成済みHTMLを変換する。

このSKILL.mdファイルの場所からの相対パスでスクリプトディレクトリのパスを決定する。

#### PDF変換

以下のコマンドを実行する：

```
uv run --project <scripts-dir> <scripts-dir>/generate_pdf.py --input <HTMLファイルパス> --output <出力ディレクトリ> --skill-name <スキル名>
```

#### DOCX変換

以下のコマンドを実行する：

```
uv run --project <scripts-dir> <scripts-dir>/generate_docx.py --input <HTMLファイルパス> --output <出力ディレクトリ> --skill-name <スキル名>
```

オプションで`--template <パス>`を指定し、`assets/`のカスタムDOCXテンプレートを使用できる。

**重要**: `--project <scripts-dir>` オプションにより、`uv run` はそのディレクトリの `pyproject.toml` から依存パッケージを自動解決する。
シェル固有の構文（例: bash）は使用しない。コマンドはmacOSとWindowsの両方で動作する必要がある。

最終形式がPDFまたはDOCXの場合、中間HTMLファイルとstyle.cssはユーザーの希望に応じて
保持または削除する。

#### 出力先

全ての出力ファイルは、対象スキル名と同名のサブディレクトリ内に配置する：

```
<出力ベース>/<スキル名>/
├── <スキル名>.pdf          # PDF形式の場合
├── <スキル名>.docx         # DOCX形式の場合
├── <スキル名>.html         # HTML形式の場合（または中間ファイルとして保持）
├── style.css               # HTML形式の場合
└── images/                 # HTML形式で画像がある場合
    └── ...
```

- ユーザーが出力ディレクトリを指定した場合、それをベースとして使用する。その中にスキル名サブディレクトリを作成する。
- 指定がない場合、現在のコンテキストから適切な書き込み可能ディレクトリを判断する（例: `~/work/`またはプロジェクトの出力ディレクトリ）をベースとする。

### Step 9: 出力の検証

生成されたファイルを確認する：
- 出力サブディレクトリ`<スキル名>/`が期待されるパスに存在すること。
- メインファイルが存在し、ファイルサイズが0バイトより大きいこと。
- PDF: `%PDF`ヘッダーバイトで始まることを確認する。
- DOCX: 有効なZIPアーカイブであることを確認する（DOCXはZIPベースである）。
- HTML: `<スキル名>.html`と`style.css`の両方が存在し、空でないことを確認する。

### Step 10: 完了報告

成功時、以下を呼び出し元に返す：

```
ドキュメント生成が完了しました。
ファイル名: <ファイル名>
パス: <出力サブディレクトリの絶対パス>
ファイルサイズ: <人間が読みやすい形式のサイズ>
```

返却前に残存する一時ファイルを全て削除する。
