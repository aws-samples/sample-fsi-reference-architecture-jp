# FISC 安全対策基準 実務基準の対策 [勘定系 / Core Banking]

この表には FISC 安全対策基準（第 14 版）の実務基準に対する BLEA for FSI での対策についてのみ記載する。総合的なシステム全体の安全対策に関しては、ユーザーアプリケーション側の実装とシステム運用・開発プロセス等での対策を含めて検討する必要がある。

- 「共通統制環境」列 = 共通統制環境（ガバナンスベーステンプレート）の対策内容
- 「勘定系ワークロード」列 = 金融ワークロードテンプレートの対策内容（勘定系）
- 「使用者側での追加対策」列 = 使用者側での追加の対策の例／考慮事項

## 主要な規制上の考慮事項（勘定系ワークロード観点）

- **可用性・災害対策（実 73〜実 88）**: マルチリージョン/マルチアベイラビリティーゾーン構成、セカンダリリージョンの構築、高可用性の AWS マネージドサービスの利用により対応する。
- **リージョン切り替え・復旧（実 71、実 104）**: Step Functions によるリージョンの自動切り替え・切り戻し、サイバーイベント発生時の復旧方法を解説する。
- **バックアップ・イミュータブル保護（実 39、実 73-1、実 106）**: AWS Backup、ボールトロック（ガバナンスモード）、Logically air-gapped Vault、DynamoDB の PITR、ECR クロスリージョンレプリケーションにより対応する。
- **暗号化（実 3、実 13、実 30、実 89）**: AWS KMS による暗号化と鍵管理。TLS による転送時暗号化は利用者側で実装する。
- **監視・ロギング（実 10、実 46、実 72、実 101〜実 103）**: VPC フローログ、ALB アクセスログ、CloudWatch によるモニタリング、CloudWatch Synthetics Canary による外形監視で対応する。
- **脆弱性・脅威対策（実 14、実 20、実 21、実 32）**: WAF、VPC エンドポイント、セキュリティグループ、ECR ベーシックスキャン、サイバーイベント時の自動隔離ワークフローで対応する。
