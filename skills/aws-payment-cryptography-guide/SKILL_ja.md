# AWS Payment Cryptography ガイド — エージェントスキル

## 目的（Purpose）

本スキルは、**AWS Payment Cryptography（APC）** の導入・設計・移行に関するガイダンスを提供します。カード発行（イシュア）、加盟店契約（アクワイアラ）、決済サービスプロバイダ（PSP）、ネットワークプロセッサの業態の視点で、アーキテクチャパターン、移行戦略、運用のガイダンスを提供することを目的とします。

---

## ワークフロー（Workflow）

ユーザーの質問に対応する際は以下のステップに従う：

### ステップ 1 — 業態の特定

ユーザーの業態をコンテキストから判定する：

| 業態 | 判定指標 |
|---|---|
| **イシュア** | カード発行、PIN生成、ARQC検証、Select PIN、カードパーソナライゼーション |
| **アクワイアラ** | 加盟店契約、POS端末管理、PIN翻訳、P2PE |
| **PSP** | 決済ゲートウェイ、マルチアクワイアラルーティング、トークナイゼーション、決済代行 |
| **ネットワークプロセッサ** | スイッチ運用、ネットワークレベルPIN変換、スタンドインプロセシング |
| **不明** | 分類するための十分なコンテキストがない → ステップ4へ |

### ステップ 2 — 業態別参照ファイルの読み込み

業態が特定できたら、対応する参照ファイルを読み込む：

| 業態 | 参照ファイル |
|---|---|
| イシュア | `references/issuer.md` |
| アクワイアラ | `references/acquirer.md` |
| PSP | `references/psp.md` |
| ネットワークプロセッサ | `references/network-processor.md` |

このファイルをユーザーの質問に回答するための主要コンテキストとして使用する。

### ステップ 3 — 横断的トピックの読み込み（必要に応じて）

質問が複数の業態にまたがるトピックを含む場合、関連する共通参照を追加で読み込む：

| トピック | 参照ファイル |
|---|---|
| 鍵管理、TR-31、TR-34、ECDH鍵交換 | `references/key-management.md` |
| PCI DSS / PCI PIN / PCI P2PE コンプライアンス | `references/pci-compliance.md` |
| オンプレミスHSMからAPCへの移行 | `references/migration-guide.md` |
| 外部リソース（ドキュメント、ブログ、サンプルコード） | `references/external-resources.md` |

### ステップ 4 — 初期探索・概要

ユーザーの業態が不明な場合、または質問が探索的な場合：

1. `references/faq.md` を読み込む — よくある質問と概要をカバー
2. `references/decision-tree.md` を読み込む — ユースケースに基づくAPC機能選定のための構造化された判断のフレームワークを提供

ユーザーの業態と具体的なニーズを特定するための明確化質問を通じてガイドする。

### ステップ 5 — コンプライアンス免責事項

PCIコンプライアンス、セキュリティ管理、または認証範囲に関するガイダンスを提供する際は、**常に**以下の免責事項を含める：

> ⚠️ **免責事項**: 本ガイダンスは情報提供およびアーキテクチャ計画目的のみです。PCI DSS、PCI PIN、PCI P2PEのコンプライアンス要件は、認定セキュリティ評価機関（QSA）または適切なPCI認定調査機関（PFI）による認定が必要です。AWS Payment CryptographyはAWSサービス範囲として複数のPCIコンプライアンスに認証されたサービスですが、お客様のアプリケーションおよびシステム全体のコンプライアンス準拠は具体的な実装に依存します。

## 回答ガイドライン（Response Guidelines）

1. **ユーザーの業態に特化する** — 業態に合わせた推奨を行い、汎用的なガイダンスは避ける
2. **AWSドキュメントを参照する** — 公式AWSドキュメントがある場合はリンクを提供する
3. **コード例を提供する** — 有用な場合はAWS CLIやSDKのスニペットの公式ガイダンスを含める
4. **リージョンの考慮事項を強調する** — アーキテクチャ決定に関連する場合はAPCのリージョン可用性に言及する
5. **セキュリティファースト** — 鍵セキュリティやコンプライアンス態勢を損なうショートカットは決して推奨しない
6. **移行のプラグマティズム** — 移行は段階的であることを認識し、過渡期のハイブリッドアーキテクチャをサポートする
