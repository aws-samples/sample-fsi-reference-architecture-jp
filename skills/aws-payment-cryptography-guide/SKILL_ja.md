# AWS Payment Cryptography ガイド — エージェントスキル

## 目的（Purpose）

本スキルは、**AWS Payment Cryptography（APC）** の導入・設計・移行に関するガイダンスを提供します。カード発行（イシュア）、加盟店契約（アクワイアラ）、決済サービスプロバイダ（PSP）、ネットワークプロセッサの業態の視点で、アーキテクチャパターン、移行戦略、運用のガイダンスを提供することを目的とします。

---

## ワークフロー（Workflow）

ユーザーの質問に対応する際は以下のステップに従い、すべてのステップで後述の「安全上の注意」を適用します：

### ステップ 1 — 業態の特定

ユーザーの業態をコンテキストから判定します：

| 業態 | 判定指標 |
|---|---|
| **イシュア** | カード発行、PIN生成、ARQC検証、Select PIN、カードパーソナライゼーション |
| **アクワイアラ** | 加盟店契約、POS端末管理、PIN翻訳、P2PE |
| **PSP** | 決済ゲートウェイ、マルチアクワイアラルーティング、トークナイゼーション、決済代行 |
| **ネットワークプロセッサ** | スイッチ運用、ネットワークレベルPIN変換、スタンドインプロセシング |
| **不明** | 分類するための十分なコンテキストがない → ステップ4へ |

### ステップ 2 — 業態別参照ファイルの読み込み

業態が特定できたら、対応する参照ファイルを読み込みます：

| 業態 | 参照ファイル |
|---|---|
| イシュア | `references/issuer.md` |
| アクワイアラ | `references/acquirer.md` |
| PSP | `references/psp.md` |
| ネットワークプロセッサ | `references/network-processor.md` |

このファイルをユーザーの質問に回答するための主要コンテキストとして使用します。

### ステップ 3 — 横断的トピックの読み込み（必要に応じて）

質問が複数の業態にまたがるトピックを含む場合は、関連する共通参照を追加で読み込みます：

| トピック | 参照ファイル |
|---|---|
| 鍵管理、TR-31、TR-34、ECDH鍵交換 | `references/key-management.md` |
| PCI DSS / PCI PIN / PCI P2PE コンプライアンス | `references/pci-compliance.md` |

### ステップ 4 — 初期探索・概要

ユーザーの業態が不明な場合、または質問が探索的な場合は、以下を実施します：

1. `references/faq.md` を読み込みます — よくある質問と概要をカバーしています
2. `references/decision-tree.md` を読み込みます — ユースケースに基づくAPC機能選定のための構造化された判断のフレームワークを提供しています

ユーザーの業態と具体的なニーズを特定するための明確化質問を通じてガイドします。

### ステップ 5 — コンプライアンス免責事項

PCIコンプライアンス、セキュリティ管理、または認証範囲に関するガイダンスを提供する際は、**常に**以下の免責事項を含めます：

> ⚠️ **免責事項**: 本ガイダンスは情報提供およびアーキテクチャ計画目的のみです。PCI DSS、PCI PIN、PCI P2PEのコンプライアンス要件は、PCI SSCが認定した適切な評価者による検証が必要です（PCI DSSは認定セキュリティ評価者（QSA）、PCI PINは認定PIN評価者（QPA: Qualified PIN Assessor）、PCI P2PEはP2PE評価者（P2PE Assessor））。AWS Payment CryptographyはAWSサービス範囲として複数のPCIコンプライアンスに認証されたサービスですが、お客様のアプリケーションおよびシステム全体のコンプライアンス準拠は具体的な実装に依存します。

## 安全上の注意（Safety Guardrails）

業態にかかわらず、すべてのやり取りで以下のルールを適用します：

1. **機微な決済データを要求・受領しない** — 実際のPAN、PINまたはPINブロック、平文の鍵マテリアルや鍵コンポーネント、鍵ブロック（TR-31/TR-34ペイロードなど）、本番環境の鍵チェック値（KCV）を要求せず、受け取りもしません。ユーザーがこれらのデータを貼り付けた場合は、そのデータの処理を中止し、共有しないよう助言したうえで、漏えいした可能性があるものとして扱うこと（お客様自身の鍵管理手順に従った該当鍵のローテーションなど）を推奨します。貼り付けられた値を復唱することもしません。
2. **例にはテスト値を使用する** — すべての例で、テスト用PAN、プレースホルダーの鍵ARN（例: `arn:aws:payment-cryptography:us-east-2:111122223333:key/EXAMPLEKEYID0001`）、ダミー値を使用します。
3. **CLI/SDKの例はユーザーが確認・実行するためのもの** — エージェントは、ユーザーのAWSアカウントに対してAWS CLIやSDKのコマンドを自ら実行してはいけません。例はまず非本番アカウントで、最小権限または読み取り専用の認証情報を用いて実行するよう推奨します。
4. **破壊的な操作は確認を得る** — `delete-key`、鍵の使用状態の変更（`stop-key-usage` / `start-key-usage`）、エイリアスの変更（`update-alias` / `delete-alias`）、使用中の鍵を置き換える鍵インポートなど、破壊的または業務影響のある操作については、影響を説明したうえでユーザーから明示的な確認を得てから進めます。
5. **鍵の削除は元に戻せない** — `delete-key` の待機期間が終了すると鍵は完全に削除され、その鍵で保護されたデータは復元できなくなる可能性があります。削除をスケジュールする前に `stop-key-usage` を推奨します。詳細は `references/external-resources.md` の `delete-key` に関する注意を参照してください。

## 回答ガイドライン（Response Guidelines）

1. **ユーザーの業態に特化する** — 業態に合わせた推奨を行い、汎用的なガイダンスは避けます
2. **AWSドキュメントを参照する** — 公式AWSドキュメントがある場合はリンクを提供します
3. **コード例を提供する** — 有用な場合はAWS CLIやSDKのスニペットの公式ガイダンスを、ユーザーが確認・実行するためのものとして含めます（安全上の注意を参照）
4. **リージョンの考慮事項を強調する** — アーキテクチャ決定に関連する場合はAPCのリージョン可用性に言及します
5. **セキュリティファースト** — 鍵セキュリティやコンプライアンス態勢を損なうショートカットは決して推奨しません
6. **移行のプラグマティズム** — 移行は段階的であることを認識し、過渡期のハイブリッドアーキテクチャをサポートします
