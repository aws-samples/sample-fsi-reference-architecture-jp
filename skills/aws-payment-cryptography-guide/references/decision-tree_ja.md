# 判断ツリー: どの AWS 暗号化サービスを使うべきか？

このデシジョンフローを使用して、AWS Payment Cryptography（APC）が
ワークロードに適したサービスかどうかを判断してください。

---

## デシジョンフロー

```
Q1: ペイメント固有の暗号化操作を伴うワークロードですか？
    （PIN検証、PIN変換、CVV生成、ARQC検証、
     DUKPTによるカードデータ暗号化、P2PE復号）
    │
    ├─ はい → Q2へ
    └─ いいえ → AWS KMS（汎用暗号化）または AWS CloudHSM（カスタム暗号化）を検討

Q2: 専用HSMハードウェアの完全な制御が必要ですか？
    │
    ├─ はい → AWS CloudHSM（シングルテナント、FIPS 140-2 Level 3、お客様管理）
    └─ いいえ → Q3へ

Q3: HSMレイヤーにPCI PIN / PCI P2PE準拠が必要ですか？
    │
    ├─ はい → AWS Payment Cryptography ✓（PCI PIN、P2PE DMCP/KMCP/KLCP認定済み）
    └─ いいえ → Q4へ

Q4: ペイメント固有のAPI（PIN変換、ARQC検証など）が必要ですか？
    │
    ├─ はい → AWS Payment Cryptography ✓
    └─ いいえ → ユースケースに応じて AWS KMS または CloudHSM
```

## サービス比較表

| 基準 | AWS KMS | AWS CloudHSM | AWS Payment Cryptography |
|------|---------|--------------|--------------------------|
| ユースケース | 汎用暗号化 | カスタム暗号、PKCS#11 | ペイメント固有の操作 |
| テナンシー | マルチテナント | シングルテナント（専用） | マルチテナント（マネージド） |
| PCI PIN | 非対応 | お客様管理 | AWS管理、認定済み |
| PCI P2PE | 非対応 | お客様管理 | AWS管理、認定済み |
| 鍵の種類 | 対称鍵/非対称鍵 | 任意（お客様制御） | ペイメント鍵（PEK、CVK、BDK等） |
| APIスタイル | RESTful | PKCS#11、JCE | RESTful（ペイメント固有） |
| 料金 | 鍵単位 + リクエスト単位 | HSM時間単位 | 鍵単位 + API呼び出し単位 |
| 管理 | フルマネージド | お客様がクラスタ管理 | フルマネージド |

## ✅ AWS Payment Cryptography を使うべきケース

以下のいずれかに該当する場合、APCの使用を推奨します：

- [ ] PIN検証またはPIN変換を行う（例：イシュア処理、ATMアクワイアリング）
- [ ] CVV/CVV2/dCVV値の生成または検証を行う
- [ ] EMV ARQC/ARPCクリプトグラムの検証を行う
- [ ] DUKPTまたは対称ペイメント鍵によるカードデータの暗号化/復号を行う
- [ ] P2PE（Point-to-Point Encryption）復号環境を運用する
- [ ] PCI PINおよび/またはPCI P2PE認定HSMインフラが必要
- [ ] HSMハードウェアのライフサイクル、パッチ適用、コンプライアンス監査をAWSに管理してほしい
- [ ] クラスタ管理なしでペイメント暗号化操作を弾力的にスケールしたい
- [ ] オンプレミスのペイメントHSM（例：Thales payShield、Atalla）から移行する
- [ ] レガシーHSMホストコマンドインターフェースではなくRESTful APIを使いたい

---

## ❌ AWS Payment Cryptography を使うべきでないケース

以下の場合、APCは適切な選択肢ではありません：

- **汎用暗号化/復号** — S3オブジェクト、EBSボリューム、データベースフィールド、
  アプリケーションシークレットの暗号化にはAWS KMSを使用してください。
- **TLS終端または証明書管理** — AWS Certificate Manager（ACM）または
  PKCS#11対応のCloudHSMを使用してください。
- **カスタム暗号アルゴリズム** — 非標準アルゴリズム、カスタムファームウェア、
  直接的なPKCS#11/JCEアクセスが必要な場合はAWS CloudHSMを使用してください。
- **ペイメント以外のFIPS 140-2 Level 3準拠** — ペイメント以外の汎用的な
  FIPS 140-2 Level 3シングルテナント要件にはAWS CloudHSMを使用してください。
- **ペイメント以外のデジタル署名** — コード署名、文書署名、ブロックチェーン操作には
  AWS KMS非対称鍵またはCloudHSMを使用してください。
- **トークンボールト/トークナイゼーションストレージ** — APCは暗号化操作を提供し、
  トークンストレージは提供しません。DynamoDBまたは専用トークンボールトと組み合わせてください。
- **PKCS#11またはJCEインターフェースが必要** — APCはAPIのみ（REST）です。
  アプリケーションがPKCS#11統合を必要とする場合はCloudHSMを使用してください。

```
│                                  いいえ → AWS KMS / CloudHSM    │

```

## クイックリファレンス: APCの主な差別化要因

1. **ペイメント専用設計** — APIがペイメント業界の操作に直接対応
2. **コンプライアンス込み** — PCI PINおよびPCI P2PE認定はAWSが管理
3. **HSM管理不要** — クラスタのプロビジョニング、パッチ適用、ハードウェアローテーション不要
4. **弾力的スケーリング** — トランザクション量に応じて自動スケール
5. **鍵のインポート/エクスポート** — 相互運用性のためTR-31、TR-34鍵交換に対応
6. **マルチリージョン** — 地理的冗長性のため複数のAWSリージョンで利用可能
