# コンパニオンスキルの境界

SKILL.md から参照される、コンパニオンスキルが従う契約。

English version: [companion-skills.md](companion-skills.md)

## コンパニオンが足してよいもの

- 出所の種別と、その定義文の形式（[Sources](#sources)の表を拡張する）
- 既存ファイルへのセクション・フィールドの追加、データディレクトリへのファイル追加
- アドレス解決の経路（名前で呼ばれている文書をURLに変えるために、どのスキル・ツールを使うか）
- [データ取扱いとセキュリティ境界](#データ取扱いとセキュリティ境界)の2区分に加えるデータ区分と、
  そこに定めるものより**厳格な**取扱規則
- 自前の例示ストア（自組織のシステムが生む中身を示すもの）

## コンパニオンが触れてはいけないもの

- このスキルの規則を弱めること。全事実への出所、マーカーの語彙、人名と敬称の規則、パス解決順、
  書き込みスコープ、保存データを送信しないという禁止は、既定値ではなく**下限**である
- マーカーを追加すること、および既存のマーカーを再定義すること。マーカーの語彙は閉じており、
  このスキルが所有する — 読み手が5つのマーカーを一度覚えれば、6つ目を使うストアは存在しないと
  信頼できる状態を保つため。出所の種別は逆に追加へ開かれている
- データ区分の取扱規則の緩和。厳格化は可、緩和は不可
- `scripts/validate-store.py` を通らない形での書き込み

**衝突した場合はこのスキルが優先する。** それに反することを要求しているように見える
コンパニオンは、設定を誤っているか間違っている。従うのではなく衝突を報告する。

## コンパニオンが無いときの既定動作

| 論点 | 既定 |
|------|------|
| 出所の種別 | [Sources](#sources)の表のみ |
| アドレス解決 | ユーザーに置き場所を尋ね、それでも不明なときにのみ `{no-url}` を記録する |
| フィールド | [ファイル構成と記入例](#ファイル構成と記入例)のスキーマのみ。CRM識別子や担当割り当ての項目は存在しない |
| データ区分 | このスキルが定める顧客機密情報と個人情報の2区分 |

## configとコンパニオンのどちらを使うか

列やセクションを足すだけならスキーマの変更であり、configの `## Schema` からテンプレートを
編集すればよい。コンパニオンが必要なのは挙動のほうである — システムに到達する、アドレスを解決する、
自組織固有の取扱規則を適用する。
