# コンテキストストアのGit管理

SKILL.md から参照される、ストアの git リポジトリのセットアップと挙動。

English version: [git.md](git.md)


`git_enabled: true`（デフォルト）の場合、データディレクトリをgitリポジトリとして管理する：

## セットアップ
- 初回セットアップ時、データディレクトリがリポジトリでなければ `git init` を実行
- 必要に応じて `.gitignore` を作成（デフォルトは空 — すべてを追跡）
- リモートは自動設定しない。ユーザーが明示的にバックアップ用リモートを求めるまでローカルに留める

## 自動コミット
- コンテキスト更新（ファイル作成・変更）のたびに、変更ファイルをステージしてコミット
- コミットメッセージ形式: `update <customer-slug>/<file>: <簡潔な説明>`
- **人名・連絡先・機密の具体値をコミットメッセージに含めない。** ここに書いた内容は履歴に残り、
  後の編集では削除できない。区分と件数で表現する：
  - `update any-bank/people: add 1 contact (Digital Banking)`
  - `update any-bank/terms: add 1 term`
  - `update index: register new customer`
- 同一会話内の複数変更は実用的な範囲で1コミットにまとめる

## メリット
- コンテキスト変更の完全な履歴（タイムスタンプ付き）
- 差分確認と誤った更新の取り消しが可能

## リモートバックアップ
リモートへのpushは顧客機密をこの端末の外へ複製する行為であり、オプトインかつ条件付きとする：

- 自組織がこのデータ区分について承認したリモートのみ、かつ private リポジトリのみ。
  個人アカウントや公開リポジトリは認められない
- リモートはユーザーが意図的に設定する。このスキルが独自に追加することはない
- 初回push前に可視性が private であることを確認する。push後は履歴 —
  コミットメッセージに紛れ込んだ名前や数値を含む — が自分の管理外に出る

## 無効化
config.mdで `git_enabled: false` に設定すると無効化。git操作は一切行われない。
これはコンテキスト変更に対する唯一の監査証跡と唯一の取り消し手段も失うことを意味する：
更新・削除は追跡不能となり、誤った統合は復旧できない。無効化する場合は別のバックアップ手段を
用意し、このトレードオフをユーザーに伝える。
